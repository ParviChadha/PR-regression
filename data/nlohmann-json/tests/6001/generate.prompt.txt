# Pull request #6001: Binary reader and writer: remove checks that invariants make dead

## Description
## Summary

Removes runtime checks in the binary reader and writer that an earlier check on the same path already decides, so they can never fire. Each condition was shown dead by branch coverage and by a build that aborts on the removed side (see below).

Binary reader (`binary_reader.hpp`):

- `check_bson_document_size()`: `document_size < 0` — the size was rejected below 5 before it was stored.
- `get_ubjson_ndarray_size()`: `second != 'N'` — 'N' is rejected as a type marker before `second` can be set.
- `bjd_type_name(dtype) == nullptr` for an ND-array dtype — every marker `is_valid_optimized_type()` accepts for BJData has a name. Kept as a `JSON_ASSERT`.
- The early `is_bjd_excluded_optimized_type()` check in `get_ubjson_size_type()` — `is_valid_optimized_type()` a few lines later rejects the same eight markers with the same error. A 1.6M-input differential run (generated BJData/UBJSON/BSON, original vs. patched headers) found no difference in results or messages. With its only caller gone, `is_bjd_excluded_optimized_type()` itself is removed. The test in `unit-bjdata.cpp` that tied its list to the writer's `is_bjdata_excluded_type_marker()` now checks `is_valid_optimized_type()` of a BJData reader against the same markers instead.
- `input_format == bjdata` next to `is_ndarray`, next to bit 8 of the type, and next to a 'B', 'u', 'm' or 'M' marker — these only arise for BJData. The unused `bjdata` local goes with them.
- `first != npos` next to bit 8 — the bit is only set after a count was read.

Binary writer (`binary_writer.hpp`):

- MessagePack: the `<= max` halves of the negative int8/int16/int32 ladder — the ladder is in the `else` branch of `n >= 0`, after `n >= -32`.

The comments of `check_bson_document_size()` and `is_valid_optimized_type()` now describe where the removed checks are done instead.

Net: 24 insertions, 52 deletions in `include/`. The only test change is the lookup-table test above. Every other test still passes, and no line of the removed code was ever executed by a test.

## How the checks were found and verified

1. Branch coverage of the whole test suite (clang `-fprofile-instr-generate`) plus 24,380 mutated JSON and binary inputs through the `tests/src/fuzzer-*.cpp` drivers listed the branch sides never taken in `include/nlohmann/`.
2. Each candidate was read for the invariant that makes it dead and the line that establishes it (the commit message names them).
3. A copy of the tree with `abort()` on the supposedly dead side of every check was run through the full test suite under ASan/UBSan, the fuzz corpora and dedicated drivers: no trap fired. (One claim was disproved this way and is not part of these PRs.)
4. With the checks removed, the full test suite passes under ASan/UBSan, and a wide translation unit compiles without a new warning under the CI clang flag set (C++11 and C++17, with and without `JSON_DIAGNOSTICS` / `JSON_DIAGNOSTIC_POSITIONS`).

The full list of findings, including checks that are dead only in the shipped configurations and were left in place, is in a separate report; this PR covers the high-confidence items of its area only.

## Breaking changes

No breaking changes. All removed checks are in `detail::binary_reader` and `detail::binary_writer`, and no input or value reaches a removed side, so every output, error message and exception stays the same.
