# Pull request #5936: Fix self-aliasing in json_pointer::operator/= and patch_inplace

## Description
Two functions misbehaved when an argument was the object itself:

- `json_pointer::operator/=(const json_pointer& ptr)` passed iterators into its own token vector to `std::vector::insert` when called as `p /= p`. That is undefined behavior. With libstdc++ (gcc 16), `/a/b` appended to itself gave `/a/b//` instead of `/a/b/a/b`. The operator now appends a copy when `&ptr == this`.
- `basic_json::patch_inplace(const basic_json& json_patch)` iterates the patch while changing `*this`, so `j.patch_inplace(j)` read freed memory (heap-use-after-free under ASan). When the patch is the value itself, the function now applies a copy of it. The result equals `j = j.patch(j)`.

A patch stored inside the value, such as `j.patch_inplace(j["patch"])`, is still undefined behavior and is now documented. Copying every patch would close it, but it roughly doubled the time of a 20 000-operation patch (3.3 ms to about 6.6-8.2 ms), so only the self case is handled.

Tests were added to `unit-json_pointer.cpp` and `unit-json_patch.cpp`; both fail without the fix (gcc 16, and clang with ASan/UBSan) and pass with it. The docs of `operator/=` and `patch_inplace` are updated with 3.13.0 version-history entries. Found during a review of the JSON Pointer, JSON Patch, `diff` and Merge Patch implementations against their RFCs and docs.

## Breaking changes

No breaking changes. Both cases were undefined behavior before (a precondition violation in `operator/=`, use-after-free in `patch_inplace`), so no valid program depended on the old behavior. Signatures, ABI and behavior for non-aliasing arguments are unchanged.

## Discussion before merge
- gregmarr: If diagnostics is enabled, should it check the parents of `json_patch` to see if any of them are `this`?  Is that too much of an expense to guard against something that this shouldn't be doing?  Maybe it can be an assert so it's debug only.
- nlohmann: Good point, and it is cheap enough to do more than assert: walking `json_patch.m_parent` up to the root is O(depth), negligible next to applying the patch. With `JSON_DIAGNOSTICS` enabled, `patch_inplace` now also applies a copy when `this` is an ancestor of `json_patch`, so `j.patch_inplace(j["patch"])` is well-defined and equals `j = j.patch(j["patch"])` (fixed in `95519dbbc`, with a test and updated docs).

Without `JSON_DIAGNOSTICS` there are no parent pointers, so that case remains documented undefined behavior; copying every patch would have roughly doubled the time of a 20 000-operation patch.
