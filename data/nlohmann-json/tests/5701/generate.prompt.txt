# Pull request #5701: Copy a pair-shaped array value under JSON_BRACE_INIT_COPY_SEMANTICS

## Description
## Summary

With `JSON_BRACE_INIT_COPY_SEMANTICS` defined to `1`, brace-initializing a `basic_json` from a single JSON value
decided whether to copy that value or wrap it into an object by inspecting the value's *runtime* shape. A JSON
value that happens to be a two-element array whose first element is a string, such as `["key", 42]`, was turned
into an object (`{"key":42}`) instead of being copied, while an array like `[1, 2]` was correctly copied. The same
happened for `json j = {arr};` and for an rvalue such as `json j{json::array({"key", 42})}`.

## Changes

- `include/nlohmann/detail/json_ref.hpp`: `json_ref` now records whether it was constructed from a braced list
  (`json_ref(std::initializer_list<json_ref>)`, used for a nested braced list such as the inner `{"key", "value"}`
  of `{{"key", "value"}}`) via a new `braced_list` flag and `is_braced_list()` accessor. Every other constructor
  (from a value, moved-from value, or via the templated forwarding constructor) leaves it `false`.
- `include/nlohmann/json.hpp`: the initializer-list constructor now copies or moves a single element under
  `JSON_BRACE_INIT_COPY_SEMANTICS` *before* checking whether the list describes an object, but only when that
  element is not itself a braced list (`!init.begin()->is_braced_list()`). This makes a JSON value always copied
  regardless of its shape, while a pair *written* as a braced list in the source still creates an object, matching
  the documented exception.
- `docs/mkdocs/docs/api/macros/json_brace_init_copy_semantics.md`: clarified that the "still creates an object"
  exception is based on how the pair is written, not on the shape of its value, with the `["key", 42]` example.

## Tests

Added a section to `tests/src/unit-brace-init-copy-semantics.cpp` (regression for #5662) covering `json j{arr}`,
`json j = {arr}`, and the rvalue case `json j{json::array({"key", 42})}` for a pair-shaped array value, checking
each is a copy (`is_array()` and equality with the original), alongside the existing coverage that a braced pair
such as `{{"key", "value"}}` still creates an object.

- Built and ran the new test against develop's unmodified headers: it fails exactly as described (the three new

- Verified the amalgamated `single_include/nlohmann/json.hpp` compiles and passes the new test.

## Public API

No breaking changes. `JSON_BRACE_INIT_COPY_SEMANTICS` is not part of any released version yet (added for the
unreleased 3.13.0), and this only corrects its behavior to match the documented "single-element brace
initialization copies/moves the element" semantics for a value that happens to look like a `[string, value]` pair.

## Linked issue #5662: JSON_BRACE_INIT_COPY_SEMANTICS: json j{arr} turns an array like ["key", 42] into an object
### Description

With `JSON_BRACE_INIT_COPY_SEMANTICS` defined to `1`, brace-initializing a `basic_json` from a single JSON value does not copy that value if the value is a two-element array whose first element is a string. {
    std::ifstream file(filename, std::ios::binary);
    file.unsetf(std::ios::skipws);

    file.seekg(0, std::ios::end);
    const auto size = file.tellg();
