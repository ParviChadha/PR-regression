# Pull request #5930: Fix BSON binary subtype 0x02 and check the declared document size earlier

## Description
## Summary
- **Subtype 0x02 ("binary (old)")**: `to_bson` wrote it without the inner int32 length that the specification requires (`int32 byte*`); pymongo and libbson reject those bytes. The writer now emits outer length = size + 4, subtype `0x02`, inner int32 = size, payload. `from_bson` validates the inner length (= outer − 4, else `parse_error.112`, matching the bson-corpus decode errors) and returns only the payload, so the round trip holds. Cross-checked with pymongo (both directions) and the mongodb bson-corpus `binary.json`.
- **Document size** is now checked against the content earlier (size ≥ 5, embedded documents end before their parent, element headers fit), not only at the terminator. Same error id `parse_error.112`; `strict=false` still does not skip it.
- UUID/MD5 payload lengths are documented as not checked (not rejected). Docs also gain the lenient-read list (duplicate keys, embedded NUL, trailing bytes), the corrected key-validation statement, a BSON example for `out_of_range.415`, and the member order on write.

## Breaking changes
No API or ABI change; behaviour changes without an opt-in macro (the old subtype 0x02 output was a bug that other decoders reject):
1. `to_bson` output for binaries with subtype 2 is 4 bytes longer; all other subtypes are byte-identical.
2. `from_bson` now rejects subtype 2 input without the inner length, with a mismatched one, or with an outer length below 4 (`parse_error.112`). BSON written by this library with subtype 2 until now is not readable any more (it would otherwise be misread) and must be written again.
3. Document-size errors are reported earlier: error id unchanged, but message, byte position and the number of SAX events for already invalid input change. A differential fuzz (old vs. new, ~44,000 mutated documents, DOM and SAX, strict and non-strict) found no input accepted before and rejected now other than old-format subtype 2, and none rejected before and accepted now.

## Commit message
* Write and read the inner length of BSON binary subtype 0x02

The BSON specification defines the payload of the "binary (old)" subtype
0x02 as an int32 followed by that many bytes. to_bson wrote the plain
payload instead, so decoders such as pymongo and libbson-based readers
rejected the bytes, and from_bson returned the inner length as part of the
payload (documented as lenient behavior in gh-5333).

The writer now emits the outer length (payload + 4), the subtype, the inner
int32 holding the payload size, and the payload. The reader requires an
outer length of at least 4 and an inner length equal to the outer length
minus 4 (the cases the bson-corpus lists as decode errors), reports parse
error 112 otherwise, and returns only the payload. Both directions change
together so that the round trip keeps working.

The single-reservation fast path for scalar entries declines subtype 0x02
because it has no room for the inner length.

This is a deliberate exception to the opt-in rule for behavior changes:
the previous output was invalid BSON.

Signed-off-by: Niels Lohmann <mail@nlohmann.me>
