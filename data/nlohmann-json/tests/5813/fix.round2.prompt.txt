## Linked issue #5812: Mark json_fwd.hpp as exported by json.hpp for include-what-you-use / clang-tidy misc-include-cleaner
### Description

`nlohmann/json.hpp` includes `nlohmann/json_fwd.hpp`, which is the only header that declares the `nlohmann::json` alias (`using json = basic_json<>;`), but the include is not marked as exported. Include analysers that follow the IWYU model, such as clang-tidy's `misc-include-cleaner` and include-what-you-use, therefore attribute the `nlohmann::json` name to `json_fwd.hpp` and the class members to `json.hpp`.

As a result:

- Any source that names `nlohmann::json` and uses it is told to include **both** headers, although `json.hpp` already provides everything `json_fwd.hpp` declares.
- A source whose only uses are implicit (for example brace-initialising a `json` value) is told that `json_fwd.hpp` is sufficient. Applying the suggested fix replaces `json.hpp` with `json_fwd.hpp` and the code stops compiling with "implicit instantiation of undefined template `nlohmann::basic_json<>`".

### Reproduction

```cpp
#include <nlohmann/json.hpp>

auto Make() -> nlohmann::json { return { { "a", 1 } }; }
```

`clang-tidy --checks=-*,misc-include-cleaner` reports that no header providing `nlohmann::json` is directly included and suggests adding `<nlohmann/json_fwd.hpp>`.

### Suggested fix

Mark the include in `json.hpp` (and the amalgamated single header's equivalent) as exported:

```cpp
#include <nlohmann/json_fwd.hpp> // IWYU pragma: export
```

Both clang-tidy's include-cleaner and include-what-you-use honour this pragma, so users would only need `json.hpp` in sources and could keep `json_fwd.hpp` for headers that only need the declaration.

### Version

3.11.3, observed with clang-tidy 23 (`misc-include-cleaner`).

### Workaround

Add `nlohmann/json_fwd\.hpp` to `misc-include-cleaner.IgnoreHeaders`.
