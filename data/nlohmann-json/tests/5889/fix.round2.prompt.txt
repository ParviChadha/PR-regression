# Pull request #5889: json_view: indented and ensure_ascii dumps through the fast writer

## Description
`json_view::dump()` had a fast writer only for compact output. Indented output and `ensure_ascii` went through a generic walk that calls `put()` per token and `memset` per line break.

1. **Write the indented output of json_view's `dump()` with the fast writer.**
   - A line break is a copy of a 64-byte ruler.
   - The indented walks are out of line (`dump_pretty()`): inlined next to the compact walk, they made compact dumps of integer arrays 7 % slower.
2. **Scan the strings of json_view's `dump()` with `ensure_ascii` 16 bytes at a time.**
   - SSE2/NEON, with fast paths for 2-byte and 3-byte UTF-8.
   - The generic walk is removed.
3. **Find the end of the plain run of a decoded string 16 bytes at a time with SSE2.**
   - x86 only; NEON keeps the 8-byte scan.

## Commit message
* Write the indented output of json_view's dump() with the fast writer

The compact writer of dump() (cursor in a register, fixed-size copies of
tokens) served dump(-1) only; every dump(indent), and everything with
ensure_ascii that was indented, went through a generic walk that calls put()
for each token and put_repeated() (a memset call) for each line break. The

the generic walk is gone. A line break is a copy of a 64-byte ruler (a line

into dump() next to the compact ones, they made compact dumps of integer

runs are found by the lexer's validating scan (a scalar validation of every
