# Pull request #5854: Match literals without a stack array and keep parser states in bytes

## Description
## Summary

Two costs that every token pays, found in the assembly of the token dispatch:

- **A stack canary on every token.** `scan_after_whitespace()` built the expected text of `true`, `false` and `null` in local `std::array` objects. With `-fstack-protector-strong`, which is the default of Ubuntu's GCC and of other distributions, any local array makes the compiler protect the whole function. So the canary was set and checked for every token, not only for literals: the `%fs:0x28` load alone was 11 % of the function's samples.
  - `scan_literal()` now takes the text after the first character as a string literal, with its length as a template parameter.
  - For contiguous input it compares the rest at once and falls back to the byte loop on a mismatch, so errors are reported at the same character.
  - It is out of line, which keeps the token dispatch small. Inlined, Clang's dispatch grew from 233 to 278 instructions and became slower.
- **`std::vector<bool>` for the parser's nesting state.** GCC calls its `push_back()` out of line. It is a `std::vector<std::uint8_t>` now.

Stacked on the previous PR.

* Match literals without a stack array and keep parser states in bytes

local std::array objects. With -fstack-protector-strong (the default of

The parser kept the nesting of arrays and objects in a std::vector<bool>,
whose push_back() GCC calls out of line; it is a std::vector<std::uint8_t>
now.
