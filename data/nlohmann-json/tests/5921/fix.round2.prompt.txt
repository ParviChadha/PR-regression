Each program is compiled and run twice, once against the library before the change and once after, and the two

Rules for every program:

- Use only the library's documented public API. Never include internal headers or use detail/impl namespaces,
  private members or undocumented macros.

  enough to make differences visible, one fact per line.
- Output must be deterministic. Never print pointers or addresses, uninitialized data, the order of
  hash-based containers, timings, thread ids, random values, file paths or environment data. Print floating point

# Pull request #5921: json_view: one SIMD macro set with the library

## Description
Part of the #5869 cleanup before 3.13.0, stacked on #5920. Suggested by @gregmarr in #5628 ([comment](https://github.com/nlohmann/json/pull/5628#discussion_r4331340096)): one SIMD macro set for the library and the view.

## What changes

- **`JSON_NO_SIMD` also turns off the view's vector code.** `JSON_VIEW_NO_SIMD` is removed. The view now follows the macro that the lexer and the float writer already use (#5853), and so it shares its ABI tag `_ns`.
- **`JSON_VIEW_USE_SSSE3` is removed, with no replacement.** Like the lexer, the view skips the runtime CPU check of SSSE3 when the code is compiled for SSSE3 anyway (`__SSSE3__`, e.g. `-mssse3` or `-march=native`). A build that knows its CPU has SSSE3 but doesn't pass `-mssse3` pays one `cpuid` per process and a predicted branch. That isn't worth a macro with its own ABI tag. (The issue had floated a shared `JSON_USE_SSSE3`; #5853 never added one.)
- The ABI tags `_vns` and `_vssse3` go away, along with their macro pages and references. `nlohmann_json.natvis` is regenerated, and the generator examples and the `check_amalgamation` natvis step use `_ns`.

This leaves `JSON_NO_SIMD`, the existing `JSON_USE_SIMDUTF`, and the compiler's own `-mssse3`.

## Breaking changes

None for released versions: `JSON_VIEW_NO_SIMD` and `JSON_VIEW_USE_SSSE3` were added on `develop` for 3.13.0 and never released. Code on `develop` that defines `JSON_VIEW_NO_SIMD` should define `JSON_NO_SIMD` instead, which also affects the lexer and the float writer. `JSON_VIEW_USE_SSSE3` becomes a no-op; `-mssse3` has the same effect.

## Tests

- `test-json_view_builder_portable` builds with `JSON_NO_SIMD`. `test-json_view_builder_ssse3` builds with `-mssse3` only.
- The ABI config tests no longer expect `_vns`/`_vssse3`.
- Checked by preprocessing: NEON code is in the view by default and absent with `JSON_NO_SIMD`. On baseline x86-64, the lexer and the view both do the CPU check by default, and neither does it with `-mssse3`.
- The natvis generator options step of `check_amalgamation.yml` passes when replicated locally.
