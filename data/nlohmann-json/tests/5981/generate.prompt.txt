# Pull request #5981: UBJSON/BJData readers: read optimized arrays of numbers in one loop

## Description
Stacked on #5980.

## What

An array with a type marker for a fixed-size number gives its elements no markers. Today each element still takes one trip through `parse_ubjson_internal` and `get_ubjson_value`, and `get_number` reads it byte by byte. The types are `$U $i $I $l $L $d $D`, plus BJData's `$u $m $M`, which also cover the data of a BJData ndarray.

When the input is contiguous, `parse_ubjson_typed_run` now reads the elements that are in the input in one loop: `memcpy`, a byte swap for the format's byte order (UBJSON is big-endian, BJData little-endian), then emit. It is used for optimized arrays and for the `_ArrayData_` of BJData ndarrays. The following are read as before:
- elements the input ends before (the remaining count goes to the existing per-element path, so errors are unchanged),
- other types: `C`, `h`, `H`, `T`/`F`/`Z`, strings, containers,
- non-contiguous inputs.

## Measurements

B/A, with A = the PR below. The documents are written with `to_ubjson(j, true, true)` / `to_bjdata(j, true, true)`. In canada, the coordinate pairs become `$D` arrays of two elements, and "doubles" is an array of 100 000 doubles. Same harness as the rest of the stack.

| | GCC 13 instr | Mac instr |
|---|---|---|
| DOM read, 100 000 doubles (BJData) | **0.391** | **0.444** |
| SAX canada, UBJSON | 0.770 | 0.763 |
| SAX canada, BJData | 0.783 | 0.769 |
| DOM read canada, UBJSON | 0.933 | 0.911 |
| DOM read citm_catalog (few typed arrays), UBJSON | 0.998 | 0.998 |
| plain UBJSON/BJData (no type markers), worst of 6 rows each | 0.998 | 1.000 |

SAX over the synthetic arrays is not in the table. With a handler that only counts, the compiler folds the whole loop into a single addition, which says nothing about real handlers. A vector byte swap would not help further, because every element still costs a SAX or DOM call.

## Tests

New test cases "UBJSON/BJData optimized arrays from contiguous and non-contiguous input". Each encodes a document with typed arrays of every integer and float type (BJData also with `u`/`m`/`M` and two ndarrays), arrays of typed pairs, and a mixed array. For every truncation, they compare contiguous with non-contiguous input:
- the result,
- the exception message,
- the SAX event log,
- a SAX handler that stops after each of the first 80 events.

Planting a wrong value for signed elements makes 163 (UBJSON) and 357 (BJData) assertions fail. The full ctest suite passes with ASan/UBSan.

## Breaking changes

None. Values, error messages, error positions and SAX events are unchanged. The public API is untouched.
