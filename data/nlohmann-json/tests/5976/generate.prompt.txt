# Pull request #5976: Binary readers: swap the bytes of floats with a single byteswap

## Description
Stacked on #5975.

## What

`binary_reader::byte_swap` reversed `float` and `double` values byte by byte with a loop of `std::swap`. C++23's `std::byteswap` takes only integers. Clang merges the loop into one `bswap`, but GCC 13 does not: in callgrind it was about 7 % of the instructions for reading canada.json from CBOR.

- New `byte_swap(float&)` and `byte_swap(double&)` overloads copy the bits into a `uint32_t`/`uint64_t`, call `detail::byteswap` from `bit_ops.hpp`, and copy them back. Integers keep the existing code.
- The change applies to every reader that uses `get_number`: CBOR, MessagePack, UBJSON, BJData and BON8.
- In the CBOR reader, the 0xFA/0xFB cases call a new never-inlined `get_cbor_float<T>()`. With the overloads alone, GCC stopped inlining `input_stream_adapter::get_character()` into `parse_cbor_internal`, making CBOR from a `std::istringstream` +0.45 % slower. Moving the float reads out of `parse_cbor_value`, which is inlined into `parse_cbor_internal`, removes that. Floats inside arrays are read by #5975's scalar-run loop, which does not take this path.

## Measurements

CBOR reads, B/A, where A is #5975. Same harness as #5975: ab-harness one-binary A/B. GCC 13 instruction counts are from callgrind on x86-64. The Mac is an M1 Max with Apple clang (60 reps; time is the geomean over both code layouts).

| | GCC 13 instr | Mac instr | Mac time |
|---|---|---|---|
| DOM read canada | **0.961** | 1.000 | 1.005 |
| SAX canada | 1.000 | 1.002 | 0.995 |
| DOM read citm_catalog | 1.001 | 1.001 | 1.003 |
| SAX citm_catalog | 1.000 | 1.001 | 1.000 |
| DOM read twitter | 1.002 | 1.001 | 1.002 |
| SAX twitter | 1.000 | 0.998 | 0.999 |
| strict UTF-8, citm_catalog | 1.001 | 1.000 | 1.000 |
| `std::istringstream`, citm_catalog | 0.999 | 1.000 | 1.012 |

The Mac time rows above 1 are layout noise: the instruction counts are flat, and neither layout's confidence interval shows a slowdown. Clang already produced a single `bswap`, so the Mac gains nothing.

Variants that were measured and dropped:
- the overloads without the CBOR helper: stream +0.45 % on GCC;
- the same plus `JSON_HEDLEY_ALWAYS_INLINE` on the stream adapter's `get_character()`: no help;
- `JSON_HEDLEY_ALWAYS_INLINE` on `binary_reader::get()`. This fixes it too and is slightly faster (read canada 0.956, twitter 0.993), but it affects every binary format, and only CBOR was measured.

## Tests

The existing CBOR, MessagePack, UBJSON, BJData and BON8 tests cover float and double reads. The CBOR, BJData and BON8 tests also include NaN, infinities and negative zero. #5975's new test compares contiguous and stream input for every truncation of a document with floats. The full ctest suite passes with ASan/UBSan (184/184).

## Breaking changes

None. The values read are identical bit for bit, and the public API is unchanged.
