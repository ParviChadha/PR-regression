Each program is compiled and run twice, once against the library before the change and once after, and the two
outputs are compared. Your job is to produce programs whose output reveals whether the change altered behavior,
including side effects the author did not intend.

Rules for every program:
- It is standalone: one file with its own int main(), compiled as C++17, printing results to stdout.
- Use only the library's documented public API. Never include internal headers or use detail/impl namespaces,
  private members or undocumented macros.
- Do not judge results (no assert, no expected-value comparisons): just print what the library returns. Print
  enough to make differences visible, one fact per line.
- Output must be deterministic. Never print pointers or addresses, uninitialized data, the order of
  hash-based containers, timings, thread ids, random values, file paths or environment data. Print floating point
  values with an explicit precision. No input, files, network, threads, clocks or randomness.
- Wrap calls that may throw in try/catch and print the exception's type and message, so an exception is an
  observable result. Do not crash on purpose.

# Pull request #5884: Faster std::istream input: inline get-area path, binary reads, unbuffered streambufs

## Description
Three changes to the `std::istream` input adapter:

1. **Step over a character in the get area without leaving `get_character()`.**
   - ifstream citm -5 %, `accept()` citm -8 % (macOS instructions).
   - Linux citm 89.0 / 122.1 -> 84.6 / 118.7 M Ir.
2. **Copy small binary reads straight from the streambuf get area.**
   - CBOR, MessagePack and UBJSON from an ifstream: -4 ... -7 % (macOS).
   - UBJSON citm -10 % (Linux).
3. **Read a streambuf without a get area with a shorter path.**
   - Unbuffered streambufs vs develop: -16 ... -20 % (macOS), -8 ... -11 % (GCC), -20 ... -23 % (Clang).

## Numbers

macOS timing, develop -> this PR:

| case | ratio |
|---|---|
| ifstream twitter | 0.91 |
| `accept()` twitter | 0.90 |
| CBOR twitter | 0.83 |
| MessagePack citm | 0.87 |
| unbuffered citm | 0.73 |

`FILE*` input is unchanged (equal instructions).

## Validation

- Differential check against develop: 746,523 cases, 0 differences.
  - Inputs:
    - 1,228 corpus files, plus binary, truncated and NDJSON variants;
    - custom streambufs with get areas of 0 to 4096 bytes, and a get area that only appears later;
    - `FILE*` and pipes.
  - Compared: value, exception text, `rdstate()`, `tellg()` and the bytes left in the stream.
  - Builds: default, `JSON_DISABLE_STREAM_BULK_SCAN`, `JSON_PRECISE_STREAM_POSITION` and `JSON_DISABLE_UNLOCKED_FILE_IO`.
- 13 unit test files with ASan/UBSan, in C++11 and C++20.
