# Pull request #5979: BSON writer: write to_bson(j) in one pass, with sizes written afterwards

## Description
## What

BSON prefixes every document and array with its size in bytes. So far `to_bson()` therefore walked the value twice: `calc_bson_sizes` computed every size, and `write_bson_document` wrote. In the research for #5968, the size pass took 19–36 % of `to_bson` time.

When the output is the vector that `to_bson(j)` returns, the writer now writes everything in one walk (`write_bson_document_single_pass`):
- it writes a placeholder for the size of each document and array,
- it writes the real size there once the document or array is complete (`output_vector_sink::overwrite`).

The single pass checks every key and value as the size pass did (U+0000 in keys, UTF-8 under `strict`, binary subtypes, discarded values), in the same order, so the same exception is thrown. The partial output disappears with the vector, which is never returned. If a length would not fit BSON's 32-bit size fields, the writer drops what it has written (`output_vector_sink::rewind`) and writes the document in two passes. That reports the length error exactly as before, before anything large has been written.

The two passes stay for:
- output adapters (streams, strings, and vectors passed by reference to `to_bson(j, v)`),
- `error_handler_t::replace` and `ignore`, which change the sizes,
- integer types wider than 64 bits, which arrays of numbers would otherwise need to range-check.

- Canada (+9 %): the single pass had dropped the two-pass writer's shortcut for arrays of numbers that need no frame of their own.
- Twitter (+2.5 %): an out-of-line value check on every entry. Numbers, booleans and null now skip the check; only strings and binary values need it.

## Tests

New test case "BSON written in one pass and in two passes" in `unit-bson.cpp`. It compares `to_bson(j)` (one pass) with `to_bson(j, vector)` (two passes) for all four error handlers, and checks that the bytes and the exception messages are identical. The cases:
- the round-trip corpus;
- documents with arrays of 1–1000 elements (index names of 1–3 digits), fixed-size, mixed and nested, empty containers, and binary values with and without the old subtype 0x02;
- every kind of rejected entry (U+0000 in a key, ill-formed UTF-8 in a key, a string or an array element, a binary subtype above 0xFF, discarded values), placed before, between and after valid entries.

Planting an off-by-one in the backpatched size makes 390 of the assertions fail. The existing "lengths exceeding INT32_MAX" tests cover the fallback to two passes. The full ctest suite passes with ASan/UBSan (184/184).

## Breaking changes

None. `to_bson(j)` returns the same bytes and throws the same exceptions with the same messages. The other overloads are unchanged. The public API is untouched; `output_vector_sink` (in `detail`) gains `written()`, `overwrite()` and `rewind()`.
