# Pull request #5968: BSON reader: find C-string terminators 8 bytes at a time, skip array element names

## Description
## What

Two changes to the BSON reader (`binary_reader.hpp`). They speed up `from_bson()` and BSON `sax_parse()` and leave behaviour unchanged.

- **Terminators 8 bytes at a time.** `get_bson_cstr_bulk()` (contiguous input) looked for the `0x00` that ends a key one byte at a time. It now calls the new `find_zero_byte()` in `string_scan.hpp`, which tests 8 bytes per step with the same SWAR zero-byte test the lexer's string scanners use (`(v - 0x01…) & ~v & 0x80…`, first hit via `count_trailing_zeros`).
- **Array element names are skipped.** BSON names an array's elements `"0"`, `"1"`, … These names are never passed to the SAX parser, yet each one was copied into the key string and run through `check_string_utf8()`. They are now skipped without being copied. The exception is `error_handler_t::strict`, which still reads and checks them, so ill-formed UTF-8 in an element name is rejected exactly as before (same `parse_error.113`, same byte position). `replace`/`ignore` only ever sanitised a string that was then thrown away, so nothing observable changes for them.

This came out of a research session on whether the SIMD/SWAR techniques used for JSON text apply to the binary formats. BSON's NUL-terminated names are one of the few remaining byte scans in CBOR/BSON. More PRs (CBOR runs of scalars, strict-mode UTF-8, BSON writer size pass) may follow.
