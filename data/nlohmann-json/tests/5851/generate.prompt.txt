# Pull request #5851: Accumulate number digits while scanning them

## Description
## Summary

Parsing numbers from contiguous input scanned every digit twice. `scan_number_bulk_contiguous()` validated the token one byte at a time and copied it into `token_buffer`. The conversion then went through two out-of-line functions that read the digits again:

- `parse_float_native()` called `parse_float_significand()`, which returned its result through memory and called `std::any_of` twice per number (GCC does not inline it).
- `parse_integer_signed()` divided by ten on every digit for its overflow check.

This PR accumulates the value while the digits are validated:

- Digits are taken **eight at a time** where at least eight bytes remain: `is_eight_digits()` tests them and `parse_eight_digits()` converts them, as in fast_float.
- **Floats with at most 19 digits** go straight to `decimal_to_float()` (Clinger's fast path or Eisel–Lemire), so the float fast path has no calls left.
- **Integers with at most 18 digits** are stored without an overflow check. A narrower `number_integer_t`/`number_unsigned_t` still rejects values that do not round-trip, as before.
- **Longer tokens, and float formats other than binary32/binary64** (e.g. x87 `long double`), take the existing path. It is unchanged, except that `has_nonzero_digit()` is now a plain loop and `parse_float_significand()` is always inlined.

The stream windows of #5828 are handled like the existing fast path: a number that reaches the end of a window falls back to `scan_number()`, and the terminator is read and ungotten.

This is the first of five stacked PRs from an assembly review of the number and string parsing; the stack is based on #5828.
