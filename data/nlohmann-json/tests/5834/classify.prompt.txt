# Pull request #5834: Make flatten() linear for ordered_json

## Description
`basic_json::flatten()` was quadratic for `ordered_json`: every leaf was added with `result[path] = ...`, and `ordered_map::operator[]` searches linearly. On citm_catalog.json (25k leaves) this took 265 ms (85× the parse time) versus 5 ms for `json`.

Flattened paths are pairwise distinct by construction (RFC 6901 escaping is injective), so the lookup is unnecessary.

## Changes
- `ordered_map` gets a member `emplace_new_key(key, value)` that appends a key the caller guarantees to be absent. It goes through the existing private `append`, so growth still moves values instead of deep-copying them.
- `json_pointer::flatten` uses it via SFINAE when the object type provides it; all other object types (`std::map`, custom types) still use `operator[]`.
- With `JSON_DIAGNOSTICS`, `set_parents()` is called on the result once at the end.
- Output (including key order) is unchanged.
- Test in `unit-json_pointer.cpp`: key order for `ordered_json`, round-trip with `unflatten`, agreement with `json`, primitive/empty roots.

## Measurement
Synthetic object with 25 000 leaves, `-O2`: ~1.0 ms (2.1 ms with `JSON_DIAGNOSTICS`). `std::map` was not changed (paths are not generally sorted, so `emplace_hint` was not evaluated).

## Release notes
`ordered_json::flatten()` now runs in linear instead of quadratic time (the quadratic behavior existed in all releases since `ordered_json` was added).

## Breaking changes
None. The only API addition is the member `ordered_map::emplace_new_key`; existing behavior and output are unchanged.
