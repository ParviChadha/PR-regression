# Pull request #5836: Speed up JSON pointer parsing, formatting, comparison and lookup

## Description
## Summary

Constant-factor speedups for `json_pointer` and its users, with identical behavior (exception types, ids and messages unchanged; `reference_tokens` layout unchanged).

- **Lookup** (`get_checked`, const `get_unchecked`, `get_checked_or_null`, `contains`): access the object map / array vector directly instead of going through `at()`/`contains()`+`operator[]`; misses still go through `at()` so the exception text is identical. Array indices of up to 18 digits (9 for a 32-bit `size_type`) are parsed with a digit loop instead of `strtoull`+`errno`.
- **Non-const access** (`get_unchecked`, `get_and_create`): existing object members are found without copying the key.
- `to_string`: one reserved buffer and a new `detail::escape_into` instead of `std::accumulate` re-copying the prefix; `escape` scans once for both special characters; `unescape` moves its result.
- `split`: reserves, moves tokens, skips `~` validation/unescaping for tokens without `~`.
- `operator/`, `parent_pointer`: build the result directly with `reserve`.
- `ptr == string` (deprecated): compares in place without splitting; malformed strings still throw `parse_error.107/108`.
- `unflatten`: each key is parsed once.
- `patch`: no copies of `op`/`path`/`from`; no redundant `top()`/`at(top)` check in `add` (the following `at(parent)` reports the same error); `last_path` is moved; `move` no longer deep-copies twice; `copy` copies once.

An earlier revision moved the throw sites into out-of-line helpers. ## Commit message
* Speed up JSON pointer parsing, formatting, comparison and lookup

Signed-off-by: Niels Lohmann <mail@nlohmann.me>

* Restore unflatten() speed after the linear-time rewrite

The prefix tree introduced for linear unflatten() kept a std::map per prefix,
copied each token into it and looked every token up a second time while
creating the values. Replace the per-prefix maps by one open-addressing table
keyed by (parent, token) that refers to the parsed tokens, skip the lookups for
the prefix shared with the previous key (flattened objects are mostly sorted),
and derive the prefix numbers of the second pass from parent links instead of
lookups.

Time and memory stay linear in the pointer depth, and the result is still
independent of the iteration order of the flattened object.

Signed-off-by: Niels Lohmann <mail@nlohmann.me>

* Put [[noreturn]] before __attribute__ on the JSON pointer throw helpers

Clang 18 on Linux rejects a C++11 attribute list after a GNU
__attribute__ ("an attribute list cannot appear here").

Signed-off-by: Niels Lohmann <mail@nlohmann.me>
