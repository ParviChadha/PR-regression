# Pull request #6028: Binary readers: append strings straight from contiguous input

## Description
## Summary

`binary_reader::get_bytes()` read every string into a zero-filled `resize()` and then copied the bytes over it, so each byte was written twice. The profile of `from_cbor()` showed `std::string::_M_replace_aux`, the zero fill, at 5% of the instructions.

A string that the input holds in one block is now appended from it directly. "In one block" means that `bulk_remaining()` is at least the string's length, which covers contiguous input and the get area of a stream. The claimed length is checked against the input first, so a huge claimed length still allocates nothing it cannot fill. Other inputs and binary values keep the chunked loop.

## Measurements

`from_cbor()` and `from_msgpack()` of `twitter.json` and `citm_catalog.json` from a buffer:

- Apple M1 Max: −5.5 to −9.1%,
- x86-64, GCC 15: −6.8 to −8.6%,
- x86-64, Clang 21: −2.7 to −3.5%.

`canada.json`, which has few strings, is unchanged (same instruction counts). In the Google Benchmark suite on the M1 Max, `FromBinaryBuffer/cbor` and `/msgpack` of `twitter`, `citm_catalog` and `jeopardy` are 9–16% faster.

## Tests

All binary-format tests (CBOR, MessagePack, BSON, UBJSON, BJData, BON8, the UTF-8 error handlers, custom binary types) pass with ASan and UBSan. `fuzzer-parse_cbor` ran 1.2 M executions and `fuzzer-parse_msgpack` 3 M, without a finding.

## Breaking changes

No breaking changes. The public API and all results are unchanged.
