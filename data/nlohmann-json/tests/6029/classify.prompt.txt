# Pull request #6029: Read iterator pairs of std::string and std::vector as pointer ranges

## Description
## Summary

Before C++20, a pair of iterators of a contiguous container cannot be told from any other random-access iterator. So `json::parse(s.begin(), s.end())` on a `std::string` or a `std::vector<char>` was read one character at a time, without the bulk scans of strings, numbers and indentation. The container itself gets those scans: the container overload of `input_adapter()` already maps it to a pointer range.

The iterators of `std::string` and of a `std::vector` of 1-byte integral elements (not `bool`) are now matched exactly and mapped to the pointer range they cover. The same applies to `accept()`, `sax_parse()` and the binary readers such as `from_cbor(first, last)`. An empty range is not dereferenced. The character type stays the same, so the results and error positions do not change.

This is a new partial specialization of the existing `iterator_input_adapter_factory`, selected for these iterator types, so `input_adapter(first, last)` picks it up without any change at the call sites.

## Measurements

Apple M1 Max, C++17:

| | `twitter.json` | `canada.json` |
|---|---|---|
| `parse(s.begin(), s.end())` | 2.0× | 1.7× |
| `parse(v.cbegin(), v.cend())`, `std::vector<std::uint8_t>` | 2.0× | 1.8× |
| `accept(s.cbegin(), s.cend())` | 2.7× | 3.1× |
| `from_cbor(v.begin(), v.end())` | −8% | −23% |

## Tests

A new test case in `unit-deserialization.cpp` compares iterator pairs of `std::string` and `std::vector<char>` / `<unsigned char>` / `<signed char>` (also `const_iterator`) with the byte path (`std::list` iterators). It checks values, exception messages including positions, and `accept()`, also for the empty range. It passes in C++11 and C++20 with ASan and UBSan.

## Breaking changes

No breaking changes. The public API and all results are unchanged. Only the internal adapter type that these iterator pairs are read through changes.

+/*!
+@brief whether @a IteratorType is an iterator of std::string or of a
+       std::vector of 1-byte elements
+
+Their elements are contiguous, but before C++20 that cannot be detected from
+the iterator type (std::contiguous_iterator), so an iterator pair of them would
+be read one character at a time through the iterators. They are read as the
+pointer range they are instead, as the containers themselves are (see the
+container overload of input_adapter()). The types are matched exactly, so no
+other iterator can be mistaken for one. (std::basic_string is only matched for
+char: other character types need std::char_traits specializations that the
+standard library need not have.)
+*/
+template<typename CharType>
+struct is_byte_char_type
+{
+    // a member, not an integral_constant argument, which astyle misformats
+    static constexpr bool value = sizeof(CharType) == 1 && std::is_integral<CharType>::value && !std::is_same<CharType, bool>::value;
+};
+
+template<typename IteratorType, typename CharType, bool IsByte = is_byte_char_type<CharType>::value>
+struct is_std_contiguous_byte_iterator_impl : std::false_type {};
+
+// (the containers are only named for byte types)
+template<typename IteratorType, typename CharType>
+struct is_std_contiguous_byte_iterator_impl<IteratorType, CharType, true>
+{
+    static constexpr bool value = !std::is_pointer<IteratorType>::value
+                                  && (std::is_same<IteratorType, typename std::vector<CharType>::iterator>::value

    // string/number scanners as a plain pointer - not just the byte-at-a-time
    // fallback (see #5268 for the equivalent memcpy fast path).

    // to the byte-at-a-time scanner; everything below still has to work there.
    using adapter_type = nlohmann::detail::iterator_input_adapter<std::counted_iterator<const char*>, std::default_sentinel_t>;
    CHECK(adapter_type::supports_bulk_scan);
    CHECK(adapter_type::supports_seek);
