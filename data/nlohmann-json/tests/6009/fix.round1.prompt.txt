# Pull request #6009: Fix the red CI on develop: Visual Studio 2017 build of the BSON writer, Valgrind timeouts

## Description
`develop` (b2674a4) fails on AppVeyor and in `ci_static_analysis_ubuntu (ci_test_valgrind)`, and so does every PR based on it. Two independent causes, one commit each.

## AppVeyor: Visual Studio 2017 cannot compile `to_bson()`

All Visual Studio 2017 jobs (MSVC 19.16, `/std:c++17`) fail with

```
binary_writer.hpp(2557): error C2672: '...::write_bson_document_single_pass': no matching overloaded function found
binary_writer.hpp(2557): error C2783: 'bool ...::write_bson_document_single_pass(const BasicJsonType &)': could not deduce template argument for '__formal'
```

while compiling `to_bson()` and `to_bon8()` (e.g. in `test-guard-page_cpp17`). Since #5979, `write_bson_document_single_pass()` was a member template enabled by `is_detected<sink_written_t, SinkType>`, and MSVC 19.16 does not deduce it through the class-scope alias template.

The guard is not needed: as a non-template member function of the class template, it is only instantiated when called. Its only caller is the `write_bson_document(const BasicJsonType&, std::true_type)` overload, chosen only for sinks that have `written()`, and that overload already calls `oa.written()` and `oa.rewind()` itself. So the fix removes the `template<...>` line; nothing else changes.

## GitHub: Valgrind tests hit ctest's default timeout

On ddc34f5 (green), `test-json_view_builder_cpp11_valgrind` took 1435 s and `test-ordered_json_cpp11_valgrind` 1390 s, against ctest's default timeout of 1500 s. On b2674a4 the whole job ran 10 to 15 % slower on the same runner image (e.g. `test-regression2_cpp11_valgrind`: 1050 s → 1207 s), and both tests timed out. No code change made them slower; they had no headroom. The Valgrind tests now get `TIMEOUT 3600` (the job itself has no `timeout-minutes`, so GitHub's 6-hour limit applies).
