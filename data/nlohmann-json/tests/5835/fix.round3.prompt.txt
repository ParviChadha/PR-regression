# Pull request #5835: Speed up container destruction, iterator access and diff()

## Description
Three API-neutral speedups found in a performance survey of the non-parse API.

1. **Destroy fast path**: a freshly entered container whose children are all leaves is freed in one go (`all_children_leaves`); the walk stays non-recursive and allocation-free (tested with `ulimit -s 512` on 1M–2M deep nesting). Object of 100k ints: 41.8 → 17.4 ns/member (std::map dtor itself: 15 ns); flat array of 1M doubles 2.1 → 1.8 ns; documents unchanged.
2. **`iter_impl` fast paths**: array, then object, are checked before the type switch in `++`, `--` (prefix and postfix), `*`, `->` (arrays and objects) and `==`; `<`, `+=` and `-` stay on the switch; the cold throw in `==` moved to a `NEVER_INLINE` member. Range-for over an array 2.5 → 1.3 ns/element, `items()` over an array 2.2 → 1.0, range-for over an object 4.9 → 4.1.
3. **`diff()`**: one `find` per source key (storing `vector<const basic_json*>`), target pass skipped when no keys were added, "add" operations built lazily, children compared with `==` before their path is built; same in the iterative (deep) path. `diff(a, a + 1% changes)`: citm 1.09 → 0.70 ms, twitter 0.92 → 0.41 ms; `diff({}, citm)` 3.18 → 1.62 ms.

Reverse range iteration (`rbegin()`..`rend()`, Apple clang -O2 -DNDEBUG, best of 15): over a 1M-element array develop 3.5 ns/element, PR before this update 1.9, after 1.9 (the `--` fast path adds nothing measurable there, the reverse iterator was already well inlined); over a 200k-member object develop 8.2, before 6.2, after 6.5 (within noise).

Tests added: reverse iteration (`--`, `rbegin`/`rend`) and object `->` for `json` and `ordered_json`, comparing iterators of different containers (unit-iterators1); `diff()` round trips with reordered keys and nested add/remove/replace for both types (unit-json_patch); destruction of empty, mixed and 5000-deep containers for both types (unit-constructor2). Run with `-fsanitize=address,undefined`, also with `-DJSON_DIAGNOSTICS=1` for diagnostics.

Verification: differential fuzz of `diff` (40k random pairs, `json` and `ordered_json`, keys with `~` and `/`, reordered keys, deep nesting through the iterative path) is byte-identical to develop and `patch(diff)` round-trips. Unit tests iterators1/2, items, class_iterator, class_const_iterator, json_patch, regression2, class_parser, allocator, ordered_json/ordered_map, custom-object-key-type, diagnostics, merge_patch pass, also with `-DJSON_DIAGNOSTICS=1`.

## Breaking changes
None. No public interface, ABI or layout change; `diff()` output is identical.
