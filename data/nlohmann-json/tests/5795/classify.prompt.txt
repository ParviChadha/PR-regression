# Pull request #5795: Restore v3.12.0 support for custom object key types

## Description
Custom `object_t` types whose `key_type` is not `string_t` (for example a `std::map` keyed by a user-defined class) compiled with v3.12.0 for several APIs that unreleased changes on `develop` broke. This PR makes everything that compiled with v3.12.0 compile again, and pins it with a test.

Found while reviewing #5328, which documented a new requirement that `object_t::key_type` be implicitly convertible to `string_t`. A compile sweep (28 APIs × 5 key types × C++11/C++17, v3.12.0 vs `develop`) found these regressions:

| API | Broken by | Required since | Fix |
|---|---|---|---|
| `to_bson` | #5553 | `key_type` *is* `string_t` (all custom keys, even well-behaved ones) | write the nested entry's header where the entry is found instead of keeping a `const string_t*` to the key |
| copy of deep values; `parse`, `merge_patch`, `update`, `insert` | #5389 | `operator==` on keys (`std::map` only needs `operator<`) | `copy_keys_equal()` uses `==` if available, else pairs values via `find()` |
| `to_cbor`, `to_msgpack` | #5746, #5781, #5328 | implicit conversion to `string_t` | `write_cbor_key()` / `write_msgpack_key()`: fast path for convertible keys (as in #5328), otherwise a temporary `basic_json` as in v3.12.0; the `static_assert`s are removed |
| `at()` (key not found) | #5727 | `string_t` constructible from the key | `key_for_message()` passes non-convertible keys to `concat()` unchanged, as v3.12.0 did |

The sentence #5328 added to `object_t.md` is reverted. After this PR, the sweep shows no regressions for any key type or standard.

The key types in the new `tests/src/unit-custom-object-key-type.cpp`:
- implicit `operator std::string` and `operator==`
- implicit `operator std::string`, no `operator==`
- only `explicit operator std::string`
- no conversion, only a `to_json` overload
- the same with `size()`/`c_str()`

It tests copy (shallow and deeper than `recursion_depth_limit()`), `parse`, `merge_patch`/`update`/`insert`, `at()`, BSON (the two key types BSON supported in v3.12.0), and byte-identical CBOR/MessagePack output, shallow and deep. The deep cases cover the `*_iterative` writers.

Verified locally: the new test in C++11, C++20, and with `JSON_DIAGNOSTICS`, with the CI's `-Weverything` flags; unit-bson, unit-cbor, unit-msgpack, unit-custom-object-type, unit-element_access2, unit-constructor1 in C++11; `make amalgamate` clean.

### Breaking changes

None. This removes requirements on `object_t::key_type` that unreleased changes added after v3.12.0, including the compatibility note in #5328. Nothing changes for `string_t` keys: they still take the direct paths, and CBOR/MessagePack still writes them without a temporary `basic_json`.
