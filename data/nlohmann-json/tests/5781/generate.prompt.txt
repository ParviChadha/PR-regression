# Pull request #5781: Stop binary writers overflowing the stack on deep values

## Description
Takes over #5518 by @ayush-singh-0601 (thank you!), rebased on `develop` and with the open review comments addressed.

`to_cbor`, `to_msgpack`, `to_ubjson` and `to_bjdata` recursed once per nesting level. Parsing doesn't recurse, so a value the library happily builds could still overflow the stack when serialized. This is the crash in OSS-Fuzz issue 566583014 (`parse_cbor_fuzzer`, stack overflow in `binary_writer::write_cbor`).

Each writer now uses the same bounded descent as `dump()`: it recurses as before up to `detail::recursion_depth_limit()` levels and writes anything deeper with an explicit heap stack. The output is the same bytes as before.

## Commits

1. **Stop binary writers overflowing the stack on deep values.** The author's commit cf65ac438, cherry-picked with authorship kept and conflicts with `develop` resolved (`write_cbor_head` from #5583, `to_msgpack_length` from #5584, `is_bjdata_excluded_type_marker` from #5555). The author's second commit 7301b06ee isn't included because it only changed CBOR prefix helpers that `write_cbor_head` replaces.
2. **Redesign the iterative binary writers around a shared recursion depth limit.** Addresses the open review comments:
   - Uses `detail::recursion_depth_limit()` instead of a new limit, and `write_cbor_head` instead of the CBOR prefix helpers.
   - MessagePack array and map headers are written by one helper per container type, shared by both paths, through `to_msgpack_length` (`out_of_range.412` above `UINT32_MAX`).
   - Frames hold only containers, and a container's header is written when its frame is pushed, like `bson_frame`. There is no `started` flag. The UBJSON frame stores only the value, `prefix_required` and the iterator.
   - `is_bjdata_ndarray()` is shared by the recursive path and the iterative path.
   - Discarded values throw `type_error.321` on both paths. Strict UTF-8 key checks report the same diagnostics context on both paths.
   - The doc comments refer to the public `to_*` functions instead of to themselves.
   - Tests: round trips instead of size checks. Byte-exact output at depths limit−1 to limit+2 for CBOR, MessagePack and UBJSON. A deep object, a deep BJData ND-array and a deep discarded value. The OSS-Fuzz regression (200,000 nested arrays) for CBOR and MessagePack.

## Linked issue #5392: Stack overflow in binary format writers (CBOR/MessagePack/UBJSON/BSON) due to unbounded recursion
## Summary

The binary format **writers** (`binary_writer.hpp`) recurse once per nesting level with no depth limit, so serializing a deeply nested value crashes the process. This is the counterpart of #5104, which covers the binary *readers*; both directions are affected, and neither is fixed.

The text parser is iterative, so `json::parse` accepts input of any depth. A value that the library happily builds can therefore crash it on the way back out.

## Affected functions

- `json::to_cbor()`
- `json::to_msgpack()`
- `json::to_ubjson()` (and BJData)
- `json::to_bson()`

## Reproduction

Against `develop` (734fd305a), on macOS/arm64 with the default 8 MB stack:

```cpp
#include <nlohmann/json.hpp>
#include <string>

int main()
{
    const std::size_t depth = 200000;
    const nlohmann::json j = nlohmann::json::parse(
        std::string(depth, '[') + "0" + std::string(depth, ']'));

    const auto v = nlohmann::json::to_cbor(j);   // SIGSEGV
    return static_cast<int>(v.size());
}
```

| function | `-O0` | `-O2` |
|---|---|---|
| `to_cbor` | crashes at depth 100,000 | crashes at depth 200,000 |
| `to_msgpack` | crashes at depth 100,000 | crashes at depth 200,000 |
| `to_ubjson` | crashes at depth 100,000 | crashes at depth 100,000 |
| `to_bson` | crashes at depth 100,000 | crashes at depth 100,000 |

The depth needed varies with build and stack size, as usual for stack exhaustion; CBOR and MessagePack survive depth 100,000 at `-O2` on this machine and fail at 200,000. BSON is measured with a nested object, since BSON requires an object at the root.
