# Pull request #5878: Copy short printable-ASCII strings in dump() without starting the scanner

## Description
`dump()` now handles short strings of printable ASCII separately: strings of up to 32 bytes are checked against a 256-entry table of bytes that can be written unchanged, four bytes per step, and copied in one go if all bytes pass. Longer strings, and strings with any byte that needs escaping or UTF-8 handling, take the existing path through the vector scanner unchanged.

The idea comes from SQLite's `jsonAppendString()` (`src/json.c`), which writes strings with the same kind of table loop. For short strings, starting the vector scanner costs more than the scan itself. Most object keys and many values are this short: citm_catalog averages 8 bytes per string and jeopardy 14. 32 bytes was the best threshold on the M1. 16 bytes gained less, and 64 bytes or no limit lost again.

GCC 16 and 13 stopped inlining `put_indent()` and `put_literal()` into the pretty-printing loops once `dump_escaped()` had grown, which made indented output up to 13% slower. Both are now always inlined, like `copy_leaf_value()`.

## Performance

`json::dump()` of the parsed file, against `develop`. B/A is the ratio of medians from interleaved A/B runs, 10 rounds each; below 1 is faster. `-` is compact output, `4` indents by 4, and `ascii` is compact output with `ensure_ascii`.

## Tests

A new test case puts every ASCII character and a 2-byte character at every position of strings of 1 to 40 bytes. It compares `dump()` with the reference implementation of the existing UTF-8 tests, for all error handlers and both values of `ensure_ascii`, covering both sides of the 32-byte bound. As a check that the test can fail, marking `"` as copyable in the table makes 4,551 assertions fail.

Also run locally: `unit-serialization` with ASan and UBSan; `unit-convenience`, `unit-unicode`, `unit-json_view_dump`, `unit-regression2`, `unit-alt-string`, `unit-ordered_json` and `unit-wstring`; GCC 16 and Clang 22 with the CI warning flags; and clang-tidy 22 on `unit-serialization.cpp`.

## Public API

No breaking changes. The output of `dump()` is unchanged; only internal `detail::serializer` members change.
