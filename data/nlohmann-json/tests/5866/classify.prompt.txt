# Pull request #5866: Do not use Qt's keyword macros as identifiers

## Description
Fixes #5865.

#5836 added a `prefix_tree` member named `slots`. Qt defines `slots` as an empty macro (unless `QT_NO_KEYWORDS` is set), so including any Qt header before `json.hpp` failed to compile. This PR:

- renames the member to `table` (`include/nlohmann/detail/json_pointer.hpp`, re-amalgamated),
- adds `tests/src/unit-qt_keywords.cpp`, which defines Qt's keyword macros as Qt does (`slots`, `signals`, `emit`, `foreach`, `forever`) before including the library and exercises parsing, dumping, flatten/unflatten, JSON pointers, the binary formats, and patch/diff. With the old header, this test fails to compile with the same errors as in the issue,
- lists the check in the quality-assurance docs, next to the `<Windows.h>` check.

The bug only exists on `develop` since #5836 and is not in any release.

## Breaking changes

None. The renamed member belongs to an internal `detail` type.
