Rules for every program:

  private members or undocumented macros.
- Do not judge results (no assert, no expected-value comparisons): just print what the library returns. Print

# Pull request #5839: Move binary reader error construction out of line

## Description
## Summary
In the binary reader, `get_to()`/`unexpect_eof()`, `last_byte_error()` and several size/type helpers built `parse_error`/`out_of_range` exceptions and temporary `std::string`s inline. That kept `get_to()` from being inlined into `get_number()` (0xd0-byte frame), so every multi-byte read cost two calls.

- `report_eof()` (noinline) shared by `get_to()` and `unexpect_eof()`
- `last_byte_error()`/`unexpected_byte()` take `const char*` contexts (no string temporaries at call sites); one `last_byte_error()` with an optional tail for "…; last byte: 0x…" messages (folded; no separate `_tail` helper or `const char*` overload)
- out-of-line helpers for container size, number overflow, optimized-type and BSON errors; `container_too_large_error()` in `json_sax.hpp`

Messages, exception ids, positions and the values passed to `sax->parse_error()` are unchanged. Parser/serializer/writer showed no stable gain and are not touched.
