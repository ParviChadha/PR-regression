# Pull request #5852: Copy the text of float tokens only when a SAX handler asks for it

## Description
## Summary

After the previous PR, the biggest remaining cost of parsing floats was copying the token text into `token_buffer`: an out-of-line `std::string::append` per float, about 10 % of parsing `canada.json`. The only reader of that text is the string argument of `json_sax::number_float()`. The library's own handlers ignore it: `json_sax_dom_parser`, `json_sax_dom_callback_parser` and `json_sax_acceptor`.

This PR copies the text only when it is asked for:

- **Lazy copy:** for contiguous input, the fast path keeps a pointer to the token in the input, and `get_string()` copies it on first use.
- **Built-in handlers:** the parser passes them an empty string instead of calling `get_string()`. They are marked by the new internal trait `sax_ignores_number_text`. So `json::parse()` and `json::accept()` never copy float text.
- **Everyone else still sees the exact text:**
  - user SAX handlers, including classes derived from `json_sax_dom_parser`, which the trait does not match;
  - `JSON_DIAGNOSTIC_POSITIONS`, which reads `get_string().size()`.
- **Keys and strings** never have pending text and use the unchecked `get_string_token()`. This avoids a 2–3 % cost on string-heavy input that a check in `get_string()` caused.
- **Stream windows (#5828):** input read through a window into a `std::istream` or `FILE*` copies the text right away, because the next read may refill the window.

Stacked on the previous PR.
