# Pull request #6039: Iterator: test for objects before arrays

## Description
## What

`iter_impl`'s `operator*`, `operator->`, `operator++`, `operator--` and `operator==` test for an object before an array.

## Why

#5835 replaced the `switch` on the value type in these operators with an `if` chain that tests for an array first. Every step over an object then pays for a failed test and a taken branch. When the compiler inlines the iterator, as it does in a small loop over a document, walking a document of objects got slower than with 3.12.0. The suite didn't show it: in its large translation unit, 3.12.0's iterator calls aren't inlined, so 3.13.0 wins there anyway.

## Numbers

Apple M1 Max, Apple clang 21, `-O3 -flto -DNDEBUG`. Cycles of one walk over every value (the suite's `count_values()` in a small program of its own, the median of 5 processes of 300 walks each, `/usr/bin/time -l`):

| file | 3.12.0 | develop | this PR | vs. 3.12.0 |
| --- | --: | --: | --: | --: |
| `citm_catalog.json` | 562k | 580k | 464k | 1.21× |
| `twitter.json` | 169k | 186k | 163k | 1.04× |
| `canada.json` | 1,588k | 981k | 1,357k | 1.17× |

`canada.json` holds nothing but arrays and gives back part of the gain of #5835, but it stays faster than 3.12.0. The other orders I tried each left one of the files slower than 3.12.0 (cycles per walk, citm / twitter / canada):

| variant | `citm_catalog.json` | `twitter.json` | `canada.json` |
| --- | --: | --: | --: |
| arrays first, no hints | 498k | 175k | 1,530k |
| objects first, no hints | 515k | 180k | 1,300k |
| `switch`, as in 3.12.0 | 502k | 169k | 1,523k |

The suite's `Iterate` rows (develop plus #6029, #6031 and #6033, with and without this change; median of 12 runs, speedup over 3.12.0):

| benchmark | without | with |
| --- | --: | --: |
| `Iterate/citm_catalog` | 1.61× | 1.92× |
| `Iterate/twitter` | 1.44× | 1.53× |
| `Iterate/canada` | 2.80× | 1.98× |

The other rows that iterate or copy (`Copy*`, `DestroyOnly`, `Diff`, `Equal`, `Flatten`) stayed within ±3%.

## Tests

The full unit test suite (189 tests) passes with ASan and UBSan on macOS (Apple clang). The change only reorders branches, so no new tests.

## Breaking changes

None. The public API, the behavior and the ABI are unchanged; only the order of the type tests inside the iterator's operators changed.
