# Pull request #5920: json_view: no save() and load() on big-endian targets

## Description
Part of the #5869 cleanup before 3.13.0, stacked on #5919.

## What changes

On a big-endian target, `basic_json_document::save()` and `load()` no longer exist, instead of throwing `type_error.320` at runtime. The image format is little-endian only, so a call could never succeed there; now it fails at compile time, just like `set()` on a read-only document. Suggested by @gregmarr in #5632 ([comment](https://github.com/nlohmann/json/pull/5632#discussion_r4321789217), [clarification](https://github.com/nlohmann/json/pull/5632#discussion_r4331187395)).

`save_image()`/`load_image()` and the members `save()`/`load()` are guarded by `#if NLOHMANN_VIEW_LITTLE_ENDIAN`. The members need the guard as well, since they call the functions with a non-dependent argument. `NLOHMANN_VIEW_LITTLE_ENDIAN` comes from the target's predefined macros, so it is the same in every translation unit of a build: no ODR risk.

**Error 320 stays**, now only for "cannot save a discarded json_document". This corrects my reply on #5632, which said that `type_error.320` goes away: the discarded-document case still throws it.

## Breaking changes

None for released versions: `save()`/`load()` are new in 3.13.0. Code on `develop` that called them on a big-endian target, and therefore always threw, no longer compiles.

## Tests

- The big-endian test case checks with a detection trait that `save()`/`load()` don't exist; the little-endian tests check that they do.
- `unit-json_view_image.cpp` compiled for s390x (big-endian) in Docker; all `unit-json_view*` tests with ASan/UBSan.
- Docs: `save`, `load`, `type_error.320`, and the json_view feature page say "little-endian targets only".
