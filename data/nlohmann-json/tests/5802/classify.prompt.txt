# Pull request #5802: Throw type_error.321 for discarded values in to_bon8

## Description
`to_bon8` silently skipped discarded values, but the count marker of small arrays and objects (`0x80+N` / `0x86+N`) still counted them, so the output was malformed BON8:

| Input | Before | After |
|---|---|---|
| `[1, discarded]` | `82 91` (marker announces 2 elements, 1 follows) | `type_error.321` |
| `{"a": discarded}` | `87 61 FF` (key without value) | `type_error.321` |
| discarded at top level | empty output | `type_error.321` |

`write_bon8_value` now calls `throw_on_discarded`, like the CBOR, MessagePack, UBJSON, BJData, and BSON writers.

- tests in `unit-bon8.cpp` for discarded values at top level and nested in small/large arrays and objects
- `to_bon8.md` and the `type_error.321` entry in `exceptions.md` document the exception

BON8 support is not in any release yet (#2998), so this bug never shipped.

## Breaking changes

None. BON8 is unreleased; `to_bon8` now throws `type_error.321` where it previously produced invalid output.

This PR was prepared by Claude Code.

## Commit message
write_bon8_value silently skipped discarded values, but the array/object
count marker still counted them, so [1, discarded] produced 82 91: a marker
announcing two elements followed by one. Throw type_error.321 like the other
binary writers do, at any nesting level.
