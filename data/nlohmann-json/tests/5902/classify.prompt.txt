# Pull request #5902: from_json: number-first dispatch for arithmetic types, loop for std::array

## Description
Follow-up to #5901 for #5891: it adopts the `get_number_value()` shape of `from_json(ArithmeticType&)` that #5901 left out because it made `GetArray<std::array<int, 1000>>` 2.4x slower. This PR finds the cause and fixes it.

## Why the shape mattered

- **vector/deque speedup.** `from_json(int&)` is inlined into every per-element loop. With one switch over four cases (boolean included), clang places the `boolean` test inside the hot compare chain. With `get_number_value()` plus a cold boolean path, the three number types (`value_t` 5–7) form the main path and the boolean moves behind a single `type <= 4` branch. This makes the vector loop 31% faster and the deque loop 12% faster.
- **std::array slowdown.** `get<std::array<T, N>>()` always takes the `identity_tag` overload (the `has_non_default_from_json` path), so it is never the `std::array<T, N>&` loop. That overload is the pack expansion `{ { j.at(Idx).template get<T>()... } }`. For N = 1000, clang emits one straight-line function of about 28,000 instructions: 1,000 inlined copies of the `at()` bounds and type checks plus the conversion. Its speed depends on how that ~110 KB body is inlined and laid out, not on the conversion itself. The pinned-alignment base build alone moves it from 657 to 957 ns, so any change to `from_json(int&)` shows up there 1,000 times.

## Change

- `from_json(ArithmeticType&)` uses `get_number_value()`, then accepts a boolean on a cold path. `get_arithmetic_value()` still rejects booleans.
- New `from_json_std_array()`: it checks the size once and reads the inner array directly instead of calling `at(i)` per element. Both `std::array` paths use it:
  - `from_json(j, std::array<T, N>&)` (`get_to`), for all `T`;
  - `from_json(j, identity_tag<std::array<T, N>>)` (`get`), when `T` is trivial (`std::is_trivial`, or the two `is_trivially_*` traits in C++26, as in `binary_writer`). A trivial type can't tell default construction plus assignment from construction in place. Non-trivial and non-default-constructible element types keep the pack expansion.
- Codegen with Apple clang 21 at `-O3` on a probe TU: `from_json(identity_tag<std::array<int, 1000>>)` drops from about 28,000 instructions (1,000 `throw_array_index_out_of_range` and 986 `throw_type_must_be` call sites) to 49.

Behaviour is unchanged. Elements are still converted in order, so a type error in an earlier element is still reported before a missing element. A short array still throws `out_of_range.401` for the first missing index (via `j.at(size)`), and longer arrays and booleans convert as before. New tests in `unit-constructor1.cpp` cover these cases and also pass against the #5901 head.

from_json(ArithmeticType&) now reads numbers through get_number_value() and
