
The check now sits in the `if (negative)` block, right after the sign is skipped. Numbers without a sign take exactly the same path as before. The error code (`number_after_minus`) and the position it reports are unchanged.

**GCC `-Weffc++` (`ci_test_gcc`, the GCC compiler matrix, static analysis).** `locale_switching_token` in `unit-locale-cpp.cpp` (from #5997) held a `const char*`, so GCC asked for a copy constructor and copy assignment:

```
tests/src/unit-locale-cpp.cpp:504:8: error: 'struct {anonymous}::locale_switching_token' has pointer data members [-Werror=effc++]
```

The locale name is now a `std::string`, so no copy members need adding.
