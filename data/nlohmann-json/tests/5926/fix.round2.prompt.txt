# Pull request #5926: json_view: check_utf8 skips well-formed runs with the parser's string scan

## Description
The `check_utf8` experiment from #5869, stacked on #5924. Suggested by @gregmarr in #5630 ([comment](https://github.com/nlohmann/json/pull/5630#discussion_r4309190167)).

## What changes

Strings written into an editable document (`set()`, `push_back()`, `insert()`, keys) are checked for valid UTF-8 by `check_utf8()`. Until now, that was byte by byte.

- **Strings of 32 bytes or more** first skip their well-formed part with the parser's string scan, `scan_string_run<true>()`. It checks 16 bytes at a time with NEON, SSE2/SSSE3, or the portable code under `JSON_NO_SIMD`. The scan also stops at quotes, backslashes, and control characters; these are legal in an edited string and are skipped.
- **Errors are reported by the same code as before.** If the scan stops at ill-formed UTF-8, the byte-wise check runs from that position, so `type_error.316` has the same message and the same byte index.
- **Shorter strings keep the byte-wise check.** The vector scan costs more than it saves there: a first version that scanned every string was 14–16 % slower on 16-byte strings. The byte-wise loop is force-inlined with a constant start, so this path compiles to the code it was, plus one length test. An earlier revision called it out of line with a run-time start index; on x86 that cost about 2 extra mispredicted branches per call for short emoji strings (+5–7 %).

## Numbers

Measured with an A/B harness: both versions are linked into one binary and timed alternately. Each result is the median of the per-pair ratios, averaged over 4–6 code layouts. Pairs during which the other CPUs of the shared VPS were busy are discarded. On the VPS, an A/A check (the same tree twice) is within 1 % of 1.

**Other rows (`bench_edit`, json_view engine).** These edits write short strings and numbers.

- Time patch / base on x86-64, over 6 layouts: 0.995–1.007. The one exception is rpc at 1.013; its layouts split both ways (0.97–1.08), and in the A/A check it alone varied by up to 2.2 %.
- Instructions: rpc +0.04 %, status −0.06 %, twitter update +0.04 %, canada update +0.001 %.

Earlier single-layout runs had shown canada patch 2.5 % slower. callgrind traced that to placement alone: the instructions per function and the machine code of the hot functions were identical, and only their addresses moved.
