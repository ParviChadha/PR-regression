# Pull request #5829: Update cppcheck to 1.5.2 (Cppcheck 2.20) and fix its new findings

## Description
Supersedes the Dependabot bump of `cppcheck` from 1.5.1 to 1.5.2, whose [`ci_cppcheck` job failed](https://github.com/nlohmann/json/actions/runs/38466451463/job/115534385840). Wheel 1.5.2 ships Cppcheck 2.20.0, up from 2.17.1.

## Changes

- **Preprocessor errors** (`macro_scope.hpp:61`, `:196`: `failed to evaluate #if condition, undefined function-like macro invocation: __has_include( ... )` / `__has_attribute( ... )`): `default_defines.hpp` is a `clang -dM` dump of Hedley. It defines `JSON_HEDLEY_VERSION`, so Hedley's own fallbacks are skipped and macros like `JSON_HEDLEY_HAS_ATTRIBUTE(x)` expand to the compiler's `__has_attribute(x)`. Cppcheck 2.17 quietly evaluated such unknown invocations as 0. Cppcheck 2.20 reports a `syntaxError` instead. `cmake/ci.cmake` now generates `cppcheck_feature_tests.hpp` at configure time, which defines the eight `__has_*` operators the headers use as `0`, and passes it as a second `--include`. The file is written with CMake's `file()` because the custom target is not `VERBATIM`, and parentheses in `-D` arguments would reach `/bin/sh` unquoted.
- **`bufferAccessOutOfBounds` false positive** (`number_parse.hpp:707`): in the `float` overload of `float_from_bits`, Cppcheck sizes `value` as the `double` overload's 8 bytes. A minimal repro confirms this. `sizeof(bits32)` avoids it without a suppression. Both sides are 4 bytes, which the `static_assert` guarantees.
- Bumps `cmake/requirements/requirements-cppcheck.txt` to `cppcheck==1.5.2`.

`make ci_cppcheck` passes locally with Cppcheck 2.20.0.

## Public API

No breaking changes. The library change only swaps one `sizeof` operand for an equal one inside a `detail` function.
