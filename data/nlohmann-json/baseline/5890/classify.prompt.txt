# Pull request #5890: json_view: comparison without temporaries and a faster image float check

## Description
1. **Compare json_view values without a vector per container and a `basic_json` per number.**
   - Objects are compared in a lockstep walk over the equal text, where the member order matches.
   - A type and array-size pre-check comes first.
   - The member vectors grow geometrically.
2. **Check the float tokens of a json_document image without a sort and a scan of every character.**
   - The tokens are sorted only when they are unsorted.
   - The recorded float shape is checked 8 digits per step.
3. **No per-object allocations when `ordered_json` objects are resolved.**
   - Duplicate keys are resolved in one working vector owned by the comparison, whose capacity is reused. Before, each compared object allocated one vector, or two per side when the key order differs.
   - Objects with unique keys need no working memory at all.

## Commit message
* Compare json_view values without a vector per container and a basic_json per number

operator== of views (view/view, view/json, and editable documents) built two
vectors of members for every object it entered, sorted them with stable_sort
for every object, and converted each number to a basic_json value. It now:

- keeps the members of all open objects in one vector (reserved with
  geometric growth, so that nested objects do not reallocate), and orders
  them by insertion sort for up to 16 members, or not at all when the keys
  ascend already;
- compares numbers of one type directly, and builds a basic_json only for
  numbers of different types;
- compares short texts (keys, numbers, most strings) with two overlapping
  loads (bytes_equal(), in node.hpp);
- first walks both documents in lockstep, in the order of their text, which
  finds most pairs of equal values without the work of the comparison. The
  walk only enters an object if the comparison would visit its members in the
  same order (the object type keeps the order, the keys ascend, or all values
  are scalars), so a difference is never found later than before, and it
  records the containers it found different, so that the comparison does not
  walk them again;
- rejects values of different types and arrays of different sizes before any
  of this, and, for an object type that keeps the order, objects whose first
  (up to four) members have different keys, which ends a comparison that
  differs near the start without preparing the members.

Results are unchanged: numbers compare by value across types, duplicate keys
resolve as parse() resolves them, and objects compare in document order for
ordered_json and by key otherwise.
