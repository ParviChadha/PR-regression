Each program is compiled and run twice, once against the library before the change and once after, and the two
outputs are compared. Your job is to produce programs whose output reveals whether the change altered behavior,
including side effects the author did not intend.

Rules for every program:
- It is standalone: one file with its own int main(), compiled as C++17, printing results to stdout.
- Use only the library's documented public API. Never include internal headers or use detail/impl namespaces,
  private members or undocumented macros.
- Do not judge results (no assert, no expected-value comparisons): just print what the library returns. Print
  enough to make differences visible, one fact per line.
- Output must be deterministic. Never print pointers or addresses, uninitialized data, the order of
  hash-based containers, timings, thread ids, random values, file paths or environment data. Print floating point
  values with an explicit precision. No input, files, network, threads, clocks or randomness.
- Wrap calls that may throw in try/catch and print the exception's type and message, so an exception is an
  observable result. Do not crash on purpose.

  programs may use an API the PR adds. Cover ordinary inputs and edge cases (empty, minimum and maximum values,
  boundaries, special values, nesting, unusual types) and also neighbouring behavior the change could disturb.
- When the diff changes which types or inputs an API accepts or rejects (constraints, overloads, traits,
  conversions), test it with the detection idiom (std::void_t or requires) and `if constexpr`, so the program

  Accepting an input is not enough: also use it through every entry point that should follow (const and

# Pull request #6015: Fix the red CI on develop: json_view exception context, MSVC C4127 in the number scan, allocation sweep on Windows

## Description
Fixes the red CI on `develop` (b18b6fc7e). Three independent causes, one commit each; all three came in with PRs that were merged without a CI run.

## 1. macOS: `test-json_view_positions` (`macos-15 (16.2)`, `macos-26 (26.6)`, `xcode_standards (26)`; also Ubuntu coverage, arm64, clang 4/11, MSVC)

```
unit-json_view_positions.cpp:573: [json.exception.type_error.302] (bytes 1-4) type must be number, but is string
  == [json.exception.type_error.302] type must be number, but is string
```

#5990 kept the byte range in exceptions about the root value and, for that, dropped the `found` flag of `value_path()` in `view::diagnostics()`. A root is found and has no tokens, but a view of a value that was erased from the document is not found: without the flag it got the bytes of its stale node. The test of #5974 documents the intended behaviour (not found: no path, and with it no bytes). `diagnostics()` returns an empty context again for a value that is not found; the root keeps its range.

## 2. MSVC: `error C2220` / `warning C4127` at `builder.hpp(1177)` (all Debug Win32 jobs, `ci_module_cpp20`)

The `!negative ||` that #6006 put in front of the digit test of the number scan has a constant left operand (`negative` is a template argument). The plain test is restored; the branch behaves the same.

## 3. Windows (clang-cl, msvc-arm64, vs2026 Debug): `test-allocator` crashes

```
unit-allocator.cpp(1132): FATAL ERROR: test case CRASHED: Terminate handler called
  parse() survives a failing allocation at every point (#5985) / sax_parse into an existing value
```

With `_ITERATOR_DEBUG_LEVEL > 0`, containers allocate inside noexcept functions, so a failing allocation terminates. The sweep test of #6000 is guarded for this; the one of #5991 now has the same guard.

## Checked

Locally with clang++: `unit-json_view_positions` fails 3 assertions before and passes all 17869 after (with both macros, either one, and neither); `unit-allocator` (also with `-D_ITERATOR_DEBUG_LEVEL=2`, where the sweep is skipped), `unit-json_view`, `unit-json_view_builder`, `unit-json_view_compare` and `unit-diagnostic-positions` pass; `make amalgamate` leaves no diff. **Not verified**: the MSVC warning and the Windows crash were not reproduced (no MSVC here); the changes follow the CI logs.

## Breaking changes

No breaking changes: the first two restore the behaviour before #5990 and #6006; the third changes a test only.

    try {
        std::string s = "[10, 20, 30]";
        nlohmann::json_document doc(s);
        nlohmann::json_view v = doc.root();
        for (auto it = v.begin(); it != v.end(); ++it) {
            std::cout << it->get<int>() << " ";
        }
        std::cout << std::endl;
    } catch (const nlohmann::json::exception& e) {
        std::cout << e.what() << std::endl;
    }
    return 0;
}
