# Pull request #5990: Keep the byte range in exceptions about the root value

## Description
Fixes #5987.

With `JSON_DIAGNOSTICS` and `JSON_DIAGNOSTIC_POSITIONS` both set, an exception about the **root** value lost its `(bytes a-b)` range, because `exception::diagnostics()` returned early when the path had no tokens, before the byte range was appended. The json_view `diagnostics()` copied the same early return.

### Changes

- `detail/exceptions.hpp` and `detail/view/errors.hpp`: build the `(path) ` prefix only if there are tokens; always append the byte range.
- `detail/exceptions.hpp`: `get_byte_positions()` returns no range for a null value. Without the early return, a value-initialized iterator (`json::iterator{} == j.begin()`, `invalid_iterator.212`) would now reach it with `JSON_DIAGNOSTICS` set too and dereference the null pointer. This is the same change and test as #6003, so the two PRs can be merged in either order.
- `detail/view/errors.hpp`: the `found` result of `value_path()` is no longer needed. A value that is not found leaves no tokens, just like the root.
- Tests: root, nested and constructed values in `unit-diagnostic-positions.cpp` (runs with and without `JSON_DIAGNOSTICS`) and `unit-json_view_positions.cpp`; the value-initialized iterator comparison from #6003 in `unit-diagnostic-positions.cpp`. One existing json_view check encoded the old behaviour ("no bytes for the root with `JSON_DIAGNOSTICS`") and now expects the range.
- Docs: `json_diagnostic_positions.md` states that the root value also gets its range.

| build | root | nested |
|---|---|---|
| `JSON_DIAGNOSTICS` only | — | `(/1) ` |
| `JSON_DIAGNOSTIC_POSITIONS` only | `(bytes 0-4) ` | `(bytes 4-8) ` |
| both (before) | — | `(/1) (bytes 4-8) ` |
| both (after) | `(bytes 0-4) ` | `(/1) (bytes 4-8) ` |

A value without positions (constructed, not parsed) still gets no range and no stray whitespace.

### Performance

Only the exception-message path changes (it runs after a throw), so successful operations are unaffected.

### Public API

No breaking changes. The `what()` text of exceptions about the root value changes in builds with both macros set: it now contains the byte range, as it already did with `JSON_DIAGNOSTIC_POSITIONS` alone. Since 3.12.0.

### Verification

Both test files fail on develop with `JSON_DIAGNOSTICS=1` and pass with the fix; full `ctest` with ASan+UBSan: 188/188.

## Linked issue #5987: Exception about the root value loses its byte range when JSON_DIAGNOSTICS and JSON_DIAGNOSTIC_POSITIONS are both set
### Description

With `JSON_DIAGNOSTIC_POSITIONS` alone, an exception about the **root** value of a parsed document names its byte range, e.g. `(bytes 0-4)`. As soon as `JSON_DIAGNOSTICS` is enabled as well, the root value's exception loses the byte range, while nested values keep both the path and the range:

| build | `json::parse("true").get<std::string>()` | `json::parse("[1, true]")[1].get<std::string>()` |
|---|---|---|
| `JSON_DIAGNOSTIC_POSITIONS=1` | `[json.exception.type_error.302] (bytes 0-4) type must be string, but is boolean` | `… (bytes 4-8) type must be string, but is boolean` |
| both macros | `[json.exception.type_error.302] type must be string, but is boolean` | `… (/1) (bytes 4-8) type must be string, but is boolean` |

Nothing in the [`JSON_DIAGNOSTIC_POSITIONS` documentation](https://json.nlohmann.me/api/macros/json_diagnostic_positions/) excludes the root value; its combined example only shows a nested value, and no test combines both macros on a root exception (`tests/src/unit-diagnostic-positions.cpp` lines 195-210 cover nested values only).
