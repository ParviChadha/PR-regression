# Pull request #6003: JSON_DIAGNOSTIC_POSITIONS: comparing a value-initialized iterator throws instead of crashing

## Description
## Summary

With `JSON_DIAGNOSTIC_POSITIONS=1`, comparing a value-initialized iterator (one without a container) with another iterator crashed instead of throwing `invalid_iterator.212`:

```cpp
json j = {1, 2};
json::iterator it{};
it == j.begin(); // UBSan: member call on null pointer in exception::get_byte_positions(), then SEGV
```

`check_same_container()` builds the exception from `m_object`, which is null for such an iterator, and `exception::get_byte_positions()` dereferenced it to read the byte range. Every other configuration throws `invalid_iterator.212` ("cannot compare iterators of different containers"). The `JSON_DIAGNOSTICS` path (`exception::diagnostics()`) already guards against a null value.

`get_byte_positions()` now returns no positions for a null value, so the comparison throws `invalid_iterator.212` with the same message as without the macro.

Tests: a new test case in `unit-diagnostic-positions.cpp` compares a value-initialized iterator with a real one in both directions and with `<`.

Found by a review of runtime checks in the iterator code (the null `m_object` tests in `iter_impl` turned out to be live only without `JSON_DIAGNOSTIC_POSITIONS`).

## Breaking changes

No breaking changes. The only observable difference is that a crash (undefined behaviour) became the documented `invalid_iterator.212` exception.
