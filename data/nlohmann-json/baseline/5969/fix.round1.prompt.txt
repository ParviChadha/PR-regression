Each program is compiled and run twice, once against the library before the change and once after, and the two
outputs are compared. Your job is to produce programs whose output reveals whether the change altered behavior,
including side effects the author did not intend.

Rules for every program:
- It is standalone: one file with its own int main(), compiled as C++17, printing results to stdout.
- Use only the library's documented public API. Never include internal headers or use detail/impl namespaces,
  private members or undocumented macros.
- Do not judge results (no assert, no expected-value comparisons): just print what the library returns. Print
  enough to make differences visible, one fact per line.
- Output must be deterministic. Never print pointers or addresses, uninitialized data, the order of
  hash-based containers, timings, thread ids, random values, file paths or environment data. Print floating point
  values with an explicit precision. No input, files, network, threads, clocks or randomness.
- Wrap calls that may throw in try/catch and print the exception's type and message, so an exception is an
  observable result. Do not crash on purpose.
- Aim at the code the diff changes. Prefer calls that compile against both the old and the new library; one or two
  programs may use an API the PR adds. Cover ordinary inputs and edge cases (empty, minimum and maximum values,
  boundaries, special values, nesting, unusual types) and also neighbouring behavior the change could disturb.
- When the diff changes which types or inputs an API accepts or rejects (constraints, overloads, traits,
  conversions), test it with the detection idiom (std::void_t or requires) and `if constexpr`, so the program

  Accepting an input is not enough: also use it through every entry point that should follow (const and

# Pull request #5969: json_view: decode chains of unicode escapes in a loop

## Description
## What

After the first `\uXXXX` escape of a string, `builder::slow_string()` now decodes the escapes that follow it directly,
while the next six bytes are `\u` and four hex digits that are not a surrogate, instead of going round its main loop for
each of them. Python's `json.dumps` writes non-ASCII text like that by default (`"あいう"`).

A surrogate, a bad digit, or fewer than six bytes leave the position at the backslash: the main loop handles them as before
and reports the same error at the same position. 15 lines in `builder.hpp`, nothing else changes.

## Performance

`json_document::parse()`, A/B in one binary (this branch against `origin/develop`), 6 code layouts, 20 pairs each,
time after / before. Target: `twitterescaped.json` (simdjson-data, 549 KB, 33,036 escapes, 31,798 of them `\uXXXX`).

| row | Apple M1 Max, Apple clang 21 | x86-64 Haswell, GCC 16.2 | x86-64 Haswell, Clang 23 |
|---|---|---|---|
| **twitterescaped** | **0.896** | **0.913** | **0.909** |
| twitter, citm_catalog, canada, gsoc-2018, apache_builds | 0.995-1.003 | 0.994-1.009 | 0.977-1.009 |
| instruments, tree-pretty, github_events, random, update-center | 0.996-1.002 | 0.999-1.005 | 0.983-1.024 (1) |
| semanticscholar-corpus, twitter_timeline | 0.996, 0.988 | 1.015, 0.987 | 0.978, 1.019 |
| fuzz (60,000 generated strings, valid and malformed) | 1.001 | 0.996 | 1.011 |

(1) The `instruments` row of the Clang run is left out of the range: it shows 1.16 with a layout spread of 0.99-1.27, because the
production machine was busy and most pairs of that row were discarded by the idle gate (the same row is 0.996 in an earlier run of the same code
and 0.997-1.001 on the Mac and with GCC).

The gain is about 10 % on text that is dominated by `\u` escapes and nothing elsewhere. A profile of `twitterescaped` before the
change put about 45 % of the instructions in `slow_string()` and its hex decoding.

## Tests

New test case `json_view builder: chains of unicode escapes` in `unit-json_view_builder.cpp`: chains of every length from 1 to 40
of escapes that give one, two and three bytes of UTF-8 (upper and lower case hex), followed by the end of the string, text,
another escape, UTF-8, a surrogate pair, a lone surrogate, a bad digit, a cut; a bad digit at every position of the last six
escapes; the text cut in every place of the last three escapes; a chain of 3,000 escapes. In keys and in values, against
`json::parse()`, with and without a terminating NUL. Checked against a deliberately broken loop (surrogate check
removed: 3 test cases fail).

Run locally: all `unit-json_view*.cpp` with clang++ `-std=c++11` and the builder test with g++ 16 `-std=c++17` and with
`JSON_DIAGNOSTIC_POSITIONS`; `make amalgamate` run, `single_include` regenerated. The full CI matrix has not run.

## Breaking API

No breaking changes. Internal decoding loop only; no public signature, behaviour, error message or error position changes
(the tests compare all of them with `json::parse()`), and no change to the ABI.
