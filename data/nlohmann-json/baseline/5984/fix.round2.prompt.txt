# Pull request #5984: BSON reader: check array element names in place in strict mode

## Description
Follow-up to #5968, suggested by @gregmarr in https://github.com/nlohmann/json/pull/5968#discussion_r4428974879.

## What

With `error_handler_t::strict`, the BSON reader must reject ill-formed UTF-8 in the names of an array's elements (`"0"`, `"1"`, ...), although these names are never passed on. So far they were copied into the key buffer, only so that `check_string_utf8` had a string to look at.

The new `check_bson_cstr` checks such a name in place on contiguous input (`valid_utf8_string` on the input bytes) and skips it without copying. If the scannable input has no `\x00`-byte, or the name is ill-formed, it falls back to `get_bson_cstr`, which reads the name and reports the same error as before (same message, same byte position).

`get_bson_cstr` itself is unchanged. A first version gave it a separate `validate` parameter instead. That pushed `get_bson_cstr_bulk` over clang's inlining threshold and made the **default** (`keep`) path 7.6 % slower on x86, so this PR uses a separate function for the strict case only.

## Performance

BSON document with an array of 1,000,000 int32 values; best of 15 runs; "sax" = `binary_reader` with a no-op SAX handler, "dom" = `from_bson`.

Linux x86 (Haswell VPS, pinned core, builds with aligned functions/loops):

| | clang 18 develop | clang 18 PR | GCC 13 develop | GCC 13 PR |
|---|---|---|---|---|
| sax, `strict` | 36.1 ms | 25.7 ms (**−29 %**) | 32.9 ms | 21.3 ms (**−36 %**) |
| sax, `keep` | 17.4 ms | 17.4 ms (±0 %) | 15.3 ms | 15.1 ms (−1 %) |
| dom, `keep` | ~42 ms | ~43 ms (within DOM noise) | ~43 ms | ~43 ms (within DOM noise) |

macOS arm64 (Apple clang, GCC 16):

| | clang develop | clang PR | GCC develop | GCC PR |
|---|---|---|---|---|
| sax, `strict` | 22.1 ms | 14.8 ms (**−33 %**) | 27.6 ms | 20.0 ms (**−28 %**) |
| dom, `strict` | 26.2 ms | 18.3 ms (**−30 %**) | 26.0 ms | 21.8 ms (**−16 %**) |
| sax, `keep` | 12.4 ms | 12.1 ms | 14.2 ms | 14.0 ms |
| dom, `keep` | 16.1 ms | 15.7 ms | 15.1 ms | 15.2 ms |

With clang, the `keep` path runs the same number of instructions as develop. With GCC 16 on arm64, it runs about 9 % more instructions in the SAX benchmark, but the time is the same on both machines.

## Tests

- "BSON array element names": the ill-formed name is also rejected on non-contiguous input (`std::list`, read byte by byte); with `allow_exceptions = false` the parse result is discarded; well-formed names pass in strict mode.
- "BSON keys from contiguous and stream input": every truncation of the document now also runs in strict mode, on contiguous and non-contiguous input, and must give the same value or error as in `keep` mode. This covers the fallback when the scannable input has no `\x00`-byte.
- Disabling the in-place check, or the byte-by-byte check, makes these tests fail.

## Public API

No breaking changes. Only private members of `detail::binary_reader` change; results and error messages for every input and error handler stay the same.
